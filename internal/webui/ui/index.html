Connectivity Help

🚀 New here? Start with the one-line installer

If you are connecting a Raspberry Pi 4B and an ArduPilot flight controller to MavSphere for the first time, run this on the Pi:

curl -fsSL https://mavsphere.com/downloads/setup_pi.sh | sudo bash

This installs Docker, MAVProxy, and the agent as systemd services that start on boot. Then come back here to set your MAV ID, username, password, and serial port (see steps below).

For the full narrative setup guide including wiring diagrams, ArduPilot parameters, and troubleshooting: mavsphere.com/operators/setup

Step 1 — Which port is your flight controller on?

Run this on the Pi with the flight controller plugged in and powered:

ls /dev/ttyACM* /dev/ttyUSB* /dev/ttyAMA* 2>/dev/null

What you see tells you how it is connected:

  • /dev/ttyACM0 — USB cable (Pixhawk, Cube, most modern FCs). Most common.
  • /dev/ttyUSB0 — USB via an FTDI adapter.
  • /dev/ttyAMA0 — GPIO UART (TX/RX pins wired to the Pi header). Needs UART enabled first.

If nothing appears with USB plugged in, try a different cable. Many USB cables are charge-only and carry no data.

To enable the GPIO UART (ttyAMA0) on Ubuntu: edit /boot/firmware/config.txt, add enable_uart=1 and dtoverlay=disable-bt, then disable the serial console with sudo systemctl disable serial-getty@ttyAMA0.service and reboot. On Raspberry Pi OS: use sudo raspi-config → Interface Options → Serial Port → disable login shell, enable hardware.

Step 2 — Tell MAVProxy which port to use

The installer creates a MAVProxy systemd service. Edit it to match your port:

sudo nano /etc/systemd/system/mavproxy.service

Find the --master= argument and set it:

  • USB FC: --master=/dev/ttyACM0,57600
  • FTDI USB: --master=/dev/ttyUSB0,57600
  • GPIO UART: --master=/dev/ttyAMA0,57600
sudo systemctl daemon-reload && sudo systemctl restart mavproxy

Check it is working — you should see heartbeat lines every second:

sudo journalctl -u mavproxy -f

Step 3 — MAVLink connection setting (this page)

If you used setup_pi.sh, leave the connection type as UDP via MAVProxy, host 127.0.0.1, port 14600. This is the default and works for both USB and GPIO setups.

Step 4 — Set SYSID_MYGCS in ArduPilot

ArduPilot only accepts GCS commands from a trusted system ID. The agent uses ID 252 by default.

param set SYSID_MYGCS 252 param write

You can do this in MAVProxy, QGroundControl, or Mission Planner connected to udp://<pi-ip>:14550.

Rovers — recommended failsafe params (vehicle stops if connection drops):

param set RC_OVERRIDE_TIME 0.5 param set FS_THR_ENABLE 2 param set FS_THR_VALUE 910 param set FS_GCS_ENABLE 1 param write

Step 5 — Verify

Check the Status panel at the top of this page. Mode and Armed should update in real time. Then click Run control-path check.

  • Mode updates — MAVLink is flowing correctly.
  • Mode blank — check MAVProxy is running and the port is correct.
  • Backend disconnected — check MAV ID, username, and password above.
Advanced / developer options

Default Pi MAVProxy command (equivalent to the systemd unit)

mavproxy.py --master=/dev/serial0,57600 \ --out=udpin:0.0.0.0:14550 \ --out=udp:127.0.0.1:14600 \ --out=udpin:0.0.0.0:14602

Port map:

  • 14550 — Remote GCS (QGC / Mission Planner on another machine). udpin: means MAVProxy listens; the GCS connects to <pi-ip>:14550. Accepts telemetry but only issues authoritative commands if SYSID_MYGCS=255 (QGC default).
  • 14600 — Agent. udp: means MAVProxy pushes to the agent; the agent listens on udp:0.0.0.0:14600. Commands from the agent are accepted when SYSID_MYGCS=252.
  • 14602 — Spare remote GCS slot. Same behaviour as 14550 — a second external tool can connect here.

Note: udpin: (MAVProxy listens, remote connects to it) vs udp: (MAVProxy pushes, receiver just listens) is a meaningful distinction. The GCS ports use udpin: so any tool on the network can connect without needing the Pi's IP in advance.

SITL — direct TCP (no MAVProxy, single client)

  • Agent config → MAVLink: tcpclient:127.0.0.1:5760

SITL — with MAVProxy fan-out

mavproxy.py --master=tcp:127.0.0.1:5760 \ --out=udp:127.0.0.1:14551 \ --out=udp:127.0.0.1:14550

Agent config → MAVLink: udp:127.0.0.1:14551

Real FC — serial direct (bypasses MAVProxy)

  • Agent config → MAVLink: serial:/dev/ttyACM0:57600
  • Add user to dialout: sudo usermod -aG dialout $USER (re-login required)

Real FC — remote MAVProxy (FC on a different machine)

mavproxy.py --master=serial:/dev/ttyACM0:57600 \ --out=udp:AGENT_IP:14551 \ --out=udp:GCS_IP:14550

Agent config → MAVLink: udp:0.0.0.0:14551 (listen on all)

Sanity checks

  • sudo docker logs mavsphere-agent -f — should show heartbeat messages
  • ss -lunp | grep -E '14550|14600|14602'
  • sudo tcpdump -ni any udp port 14600
